**Panel transitions (CSS):** implement the research recipe on `.chapter-panel` — closed state `opacity: 0; transform: translateY(16px);`, `[open]` state final, transition covering `opacity`, `transform`, plus `overlay var(--dur-med) allow-discrete` and `display var(--dur-med) allow-discrete`, easing `var(--ease-inout-sine)`; `@starting-style { .chapter-panel[open] { opacity: 0; transform: translateY(16px); } }`. Backdrop: transition `background-color` from transparent with its own `@starting-style` block, landing on the existing flat `rgb(10 10 15 / 72%)` (stays a single flat alpha at every frame — a fading flat layer is fine; a gradient is not). Duration `var(--dur-med)` minimum; `var(--dur-long)` if it still feels crisp — sine ease-in-out, no jarring landings. No JS animation orchestration — @starting-style does the display jump natively.

**Hero entrance (CSS only, `.has-js`-scoped):** one-time load stagger in the concept-a idiom — `@keyframes` opacity+translateY rise on `.hero__kicker` (0ms), `.hero__h1 .line:nth-of-type(1)` (120ms), `.hero__h1 .line:nth-of-type(2)` (240ms), then a quieter fade for `.hotspot`s (staggered ~360-720ms via nth-of-type delays) and `.video-toggle`/`.topbar`. Everything scoped under `.has-js` so no-JS visitors see the finished state instantly. Runs once on load; nothing scroll-driven on the homepage.

**Reduced-motion CSS block (belt-and-braces):** `@media (prefers-reduced-motion: reduce)` forcing final visible states with `animation: none; transition: none;` for the hero entrance, hotspots, toggle, panels and backdrop (panels open/close instantly). The video side needs no CSS: video.js never calls play() under reduced motion, so the element itself displays the poster frame — that IS the static-poster rendering, and the always-visible hotspot nav satisfies "standard visible navigation" (CONB-04). No audio track exists in the files, so no-sound is structural.

**video.js extensions (extend, don't rewrite):**
1. `userPaused` flag — set true when the user pauses via the toggle, cleared when the user plays via the toggle. Programmatic resume paths below must check it: never auto-resume over an explicit user pause (WCAG 2.2.2 — the pause must stick).
2. `visibilitychange`: `document.hidden` → `video.pause()`; visible again → `attemptPlay(false)` only if `!userPaused` (battery — locked decision).
3. `IntersectionObserver` on `.hero-stage` (threshold ≈ 0.2): when the hero scrolls mostly out of view (possible on small screens where content overflows), pause; when it returns, `attemptPlay(false)` if `!userPaused`.
4. Rejection fallback hardening: a rejected `play()` (iOS Low Power Mode / autoplay policy) must leave poster visible + toggle in "Play" state and must NOT schedule retries — the only retry path is the user's own toggle press (which, as a gesture, is exactly what iOS accepts). Cannot be exercised on this Mac — verify the code path by review and note that in the SUMMARY.

Adding classes/attributes for animation must never touch copy text — copy-diff re-verifies below.
