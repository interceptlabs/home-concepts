1. **Open:** for every `[data-panel]` element (6 hotspots + topbar CTA), click → `document.getElementById('panel-' + id).showModal()`. Record the invoker in a module-level `lastInvoker` variable. showModal() gives focus-into-dialog, Esc-close, focus trap, and background inertness natively — do not hand-roll any of it.
2. **Focus return (NOT automatic — the one manual piece):** one `close` listener per dialog → if `lastInvoker` exists, `lastInvoker.focus()`. Focus must land back on the hotspot that started the sequence.
3. **Close button:** `.chapter-panel__close` click → `dialog.close()`.
4. **Panel swap (Labs → Contact):** click on `[data-panel-swap]` → `currentDialog.close()` then `showModal()` the target panel — but KEEP `lastInvoker` pointing at the original hotspot (do not overwrite with the swap button), so closing Contact after a swap returns focus to the Labs hotspot, not into a closed dialog.
5. **Close before navigating (locked call):** for every `a.panel-cta` inside a dialog, add a click listener that synchronously calls `dialog.close()` and lets the anchor's default navigation proceed. This is the cheap mitigation for the undocumented open-dialog/view-transition snapshot interaction. During browser verification below, observe whether the outgoing cross-fade looks clean and record the empirical result in the SUMMARY (this was a research open question — the answer is wanted either way).
6. Optional progressive enhancement at your discretion: `closedby="any"` attribute on the dialogs for light-dismiss (Chrome 134+/FF 141+/Safari 18.2+; harmless where unsupported).
