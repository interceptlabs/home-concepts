Create concept-b/assets/js/video.js as a vanilla IIFE ("use strict", no libraries — mirror concept-a/assets/js/motion.js's shape). Scope for THIS plan (03-03 extends this file with visibilitychange/IntersectionObserver pausing and the full iOS play()-rejection fallback — structure it so those bolt on cleanly):

1. Select `.hero-stage__video` and `.video-toggle`; bail if either is missing.
2. `prefersReducedMotion` via matchMedia. `attemptPlay(userInitiated)`:
   - If `prefersReducedMotion && !userInitiated` → return WITHOUT calling play() — CSS/poster shows the static frame (CONB-04's autoplay half lives here from day one; building attemptPlay without the gate and retrofitting it in 03-03 would mean rewriting the same function).
   - Otherwise call `video.play()`; if it returns a promise, `.catch()` → call `setToggleState(false)` (rejection = iOS Low Power Mode / autoplay policy; poster is already the video's own fallback frame — never surface an error).
3. `setToggleState(playing)`: sets `aria-pressed` ("true"/"false") and swaps the toggle's text between "Pause"/"Play" (structural chrome — the only textContent writes allowed in concept-b JS, never canonical copy).
4. Toggle click: `video.paused ? attemptPlay(true) : video.pause()` — user-initiated play is allowed even under reduced motion (WCAG gates AUTOplay, not explicit user requests). Keep state in sync via the video's own `play`/`pause` events (so 03-03's programmatic pauses update the button for free).
5. Call `attemptPlay(false)` once at startup.
